# 文本误漏判、结构完整性与速度复测

2026-11-06。本地方案已实施。DeepSeek 同组 30 个自编用例各重复 3 次，预期行为通过率从 **77/90 提升到 90/90**；教学平均耗时下降约 12%，评估平均耗时下降约 25%。本轮 Doubao 因账户欠费返回 403，不能形成有效的同版本质量/速度对照。

## 改动与边界

- Stage 4 使用服务端生成的候选 ID、完整词边界、UTF-16 位置、支持的缩写/屈折变体和结构锚点；模型单独判断语境是否合适。`One trade-off is that` 中唯一的目标短语可缩回 `One trade-off is`，不改写适用性结论。重复出现绑定各自位置，引用、否认使用、读卡与正常否定分开判断。词面命中本身不奖励使用。
- Stage 5 的三个 AI 维度和九个准则改为固定键；证据 ID 只能解析到本次冻结的可靠用户原文。短 ID 减少重复输出 UUID、引文和位置。无目标自由对话使用 null，再映射为原有空数组；summary 排在 criteria 之后，避免实测中的重复字段。
- DeepSeek 默认使用 `DEEPSEEK_ASSESSMENT_STRICT=true` 的 Beta function schema；JSON 模式仍可显式配置。接口能力参考 [DeepSeek Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/)，**本地校验始终是放行条件**。
- 本地检查结构、重复键、全部用户轮次、证据与目标覆盖。最多一次定向修复，保护已有有效字段/评分；不可解析的整体输出才允许一次完整重生成。首次 45 秒、修复最多 15 秒，仍受 worker 75 秒上限约束。失败保留可用 partial，不补造分数，不自动换供应商。
- Stage 1 明确六个根字段与 logic title/subtitle 的字符串类型，保留原有严格校验和重试。Mission 规划保留现有校验/重试。公开报告 schema、评分公式、旧结果、语音和提示暴露归因不变。

## 同组修复前后对比

[用例与预设判定脚本](../../../apps/api/scripts/evaluate_text_quality.py) 包含 24 个教学用例和 6 个评估用例。每个用例重复 3 次：每版本 90 次应用评测、81 次实际 HTTP 请求；部分转录、助手文本及空评估共 9 次按契约不调用模型。每批串行，没有同时发起两批评测；最终版本批次先于扩大的旧版本批次运行，另有较早的旧版六任务基线。网络、缓存和本机负载未完全隔离。

旧版本使用修改前快照，新旧版本均为 `deepseek-flash`、相同 authored 输入及温度/thinking 配置。不是生产用户样本，不涉及数据库或真实语音。每个预期适用性由脚本预先写定，未让模型评价自身输出；未做独立教师盲评。

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 全部预期行为符合 | 77/90 | 90/90 |
| 教学判定符合 | 62/72 | 72/72 |
| 漏确认的恰当使用次数 | 9 | 0 |
| 额外奖励的恰当使用次数 | 0 | 0 |
| 评估完整结构：3 维度 / 9 准则 | 10/15 | 15/15 |
| 具备完整报告条件的案例 ready | 6/9 | 9/9 |
| 评估预期状态/判定符合（含空、短、缺失输入） | 15/18 | 18/18 |
| 最终批次额外修复请求 | 0 | 0 |

旧版教学的 10 次不符合来自问词义、重复使用、同句混合“提及与使用”和一次仅提及；主要是 uncertain/漏确认，不能据此说旧版存在大量误奖励。旧版评估有三次“仅提及”缺维度/准则，两次短转录仅返回一个维度。新版短/缺失转录仍保持 partial，空输入仍 insufficient_data；结构补齐不代表强行打分。

| 实际请求耗时（秒） | 修复前均值 / 中位数 / 样本 P95 | 修复后均值 / 中位数 / 样本 P95 |
| --- | ---: | ---: |
| 教学，66 次请求/版 | 1.156 / 1.147 / 1.503 | 1.013 / 0.989 / 1.372 |
| 评估，15 次请求/版 | 5.584 / 5.794 / 8.000 | 4.195 / 4.403 / 4.683 |

P95 为小样本 nearest-rank，不是线上尾延迟结论。评估均值包含合约允许的 partial，不能直接解释成全部完整报告提速。单看正常使用且新旧都完整的三次报告，均值 **7.596 → 4.395 秒**。仅提及用例由快速 partial 变为完整报告，均值 **4.246 → 4.555 秒**；短转录从 **3.151 → 3.925 秒**，完整表达所有准则有额外输出成本。没有声称每一种输入都更快。

**原始 strict JSON 仍有缺陷。** 新版 15 次实际评估中，6 次在完整 JSON 对象后多一个 `}`；仅这个确认的冗余尾字符被本地移除并记录。原始无处理 JSON 语法通过为 9/15，本地处理后完整结构为 15/15。不会补齐缺失括号、删除正文、合并多个对象，重复键始终拒绝。冗余 criteria_order 仅在 null、空或恰好等于现有键集合时可忽略。本轮最终批次未触发这种兼容。

## 各文本阶段与 Doubao 可用性

另跑两轮交替供应商的六类任务，共 24 次请求。DeepSeek 12/12 ready，无重试：Stage 1 均值 **13.623 秒**，规划 **4.402 秒**，教学正常/提及 **1.278 / 1.147 秒**，评估正常/提及 **4.616 / 4.531 秒**。Stage 1、规划的这次样本量各只有 2，验证的是输出通过与调用耗时，未新增独立教学内容评分。

Doubao 12 次均 HTTP 403；额外一次最小可用性探针确认 `AccountOverdueError`，即账户欠费。失败的约 0.1–0.3 秒不计为生成速度，也不计为模型质量差。有效的同版本 Doubao 对照需恢复余额后重跑；没有修改账户或支付设置。较早可用时的 [供应商迁移对比](../text-providers-20261106/COMPARISON.md) 保留，但其旧提示词结果不能混作本版结果。

## 失败实验与复现

失败轮次全部保留，未只保留成功结果。JSON 模式固定对象试验仍出现无效 JSON；初版 strict 投影出现嵌套 anyOf 的 HTTP 400；v4 还出现重复 summary、尾括号、自由对话空对象被拒绝。最终方案修正了 schema 投影、摘要输出顺序与无目标形状，未放宽重复键或证据要求。

本轮所有保存的试验累计 346 次实际请求，另有一次最小 strict 探针和一次欠费诊断，共 348 次网络请求；其中包含被拒绝的请求，不等同于全部计费成功。每个脚本都有显式 `--live` 和单次运行请求上限。

在 `apps/api` 运行最终回归：

```sh
.venv/bin/python -m scripts.evaluate_text_quality --live --output /absolute/path/regression.json
.venv/bin/python -m scripts.compare_text_providers --live --providers ark deepseek --rounds 2 --output /absolute/path/providers.json
```

根目录 `pnpm lint`、`pnpm build`、`pnpm test` 最终通过：API 1,940 + Web 523 + Extension 124 = **2,587 项测试**。一次全量运行发现五条旧提示词文本断言，已改为检查实际固定对象 schema；另一轮原有声学子进程计时测试偶发失败，隔离复测及最终全量均通过，没有修改声学策略。最终保存的 15 份实际评估响应另用当前代码离线重放，输出与实测记录完全一致。本地开发服务与 workers 已重新启动，健康状态另见 runtime.json；没有生产部署，也未批量改写既有报告。

后续仍需不同场景、非母语表达、更长会话、真实 ASR 和独立教师评审。30 个自编用例全部通过不能证明普遍零误判；真实环境尾延迟与供应商波动仍需观测。
